# OpenAgriNet Master Data Management (MDM) — Developer & DevOps Technical Guide

**Authoritative Master Data Catalogues for Crops, Seed Varieties, Agro-Inputs, Livestock Breeds, and Administrative Geolocation**

---

## 1. Executive Summary & Architecture Overview

The **OpenAgriNet Master Data Management (MDM)** subsystem provides authoritative, standardized reference catalogues for the national agricultural registry ecosystem (Ministry of Agriculture, Agricultural Transformation Institute - ATI, Ethio-Seed, and LITS).

It serves two primary consumer groups:
1. **Internal OpenG2P Registries & Administrative Workflows**: Farmer Registry, CropSown Registry, Livestock Registry, and the OpenG2P Staff Portal for data authoring, approvals, and audits.
2. **Public & Third-Party System Integrators**: Read-only, high-performance, cached `/v1` REST APIs for lookups, dropdown widgets, data validation, and national agricultural reporting.

```
                      +-------------------------------------------------------------+
                      |                 OpenG2P Master Data Platform                |
                      |            (catalog-registry-staff-api : 8002)              |
                      +-------------------------------------------------------------+
                                     /                               \
                                    /                                 \
            [OpenG2P Staff UI: 3002]                                   [External Consumers / Registries]
            (Authoring, Intake Forms,                                  (Farmer Registry, CropSown, ODK,
             Verification, Approval)                                    Public Third Parties)
                       |                                                           |
          +------------------------+                                  +--------------------------+
          |  OpenG2P Register Core |                                  |  Canonical Read-Only     |
          |  (Metadata, RBAC, Tabs)|                                  |  FastAPI /v1 Endpoints   |
          +------------------------+                                  +--------------------------+
                       \                                                           /
                        \                                                         /
                     +---------------------------------------------------------------+
                     |              PostgreSQL (catalog_registry_db : 5445)          |
                     |  - uuid-ossp extension (public.uuid_generate_v4())            |
                     |  - Master Catalogues & Taxonomies                             |
                     |  - Live Registers: g2p_register_*_catalogs                    |
                     |  - Change History & Intake Forms                              |
                     +---------------------------------------------------------------+
```

## 2. Master Data Catalogues & Domain Schemas

All records are identified by both a **human-readable business code** (e.g. `TEFF-001`, `FERT-UREA`, `ET01`) and a **canonical UUIDv4** generated by `public.uuid_generate_v4()` for cross-registry joins.

### 2.1 Summary of Catalogues

| Catalogue Code | Register Mnemonic | Subject | Total Live Records | Domain Key / Unique Identifier |
|:---|:---|:---|:---:|:---|
| `crops` | `CropCatalog` | Agricultural Crops | **156** | `crop_code`, `uuid` |
| `seeds` | `SeedCatalog` | Seed Varieties | **1,206** | `seed_code`, `uuid` |
| `inputs` | `InputsCatalog` | Agro-Inputs & Fertilizers | **11** (extensible) | `input_code`, `uuid` |
| `livestock` | `LivestockCatalog` | Livestock Breeds | **94** | `breed_code`, `uuid` |
| `locations` | `LocationCatalog` | Administrative Geolocation | **21,053** | `location_code`, `pcode`, `uuid` |

### 2.2 Detailed Schemas

#### 1. Agricultural Crops (`crops` / `g2p_register_crop_catalogs`)
- **Key Fields**:
  - `uuid` (UUID, Primary Unique ID)
  - `crop_code` (VARCHAR, e.g., `TEFF-001`, `MAIZE-001`)
  - `crop_name` (VARCHAR, e.g., "Teff", "Bread Wheat")
  - `scientific_name` (VARCHAR, e.g., "Eragrostis tef")
  - `crop_category` (VARCHAR, e.g., `CEREAL`, `PULSE`, `OILSEED`, `VEGETABLE`, `FRUIT`, `COFFEE_SPICES`)
  - `preferred_ecological_zone` (VARCHAR, e.g., "Weyna Dega", "Dega", "Kolla")
  - `growth_cycle_days` (INTEGER)
  - `water_requirement` (VARCHAR: `LOW`, `MEDIUM`, `HIGH`)
  - `preferred_soil_type` (VARCHAR)
  - `is_active` (BOOLEAN)

#### 2. Seed Varieties (`seeds` / `g2p_register_seed_catalogs`)
- **Key Fields**:
  - `uuid` (UUID)
  - `seed_code` (VARCHAR, e.g., `SEED-TEF-QUNCHO`)
  - `variety_name` (VARCHAR, e.g., "Quncho (DZ-Cr-387)")
  - `crop_name` (VARCHAR, e.g., "Teff")
  - `breeder_source` (VARCHAR, e.g., "Debre Zeit Agricultural Research Center")
  - `release_year` (INTEGER)
  - `maturity_days` (INTEGER)
  - `potential_yield` (VARCHAR, e.g., "24-28 Quintal/Ha")
  - `is_certified` (BOOLEAN)
  - `match_status` (VARCHAR: `MATCHED`, `UNMATCHED`)

#### 3. Agro-Inputs Catalog (`inputs` / `g2p_register_input_catalogs`)
Replaced the legacy single-purpose fertilizer schema with a full **Agro-Inputs Catalog** covering 11 standardized input categories:
- **Standardized Categories (`InputCategoryEnum`)**:
  1. `INORGANIC_FERTILIZER` (NPSB, Urea, DAP)
  2. `ORGANIC_FERTILIZER` (Vermicompost, Bio-slurry)
  3. `BIO_FERTILIZER` (Rhizobium, Bio-inoculants)
  4. `MICRONUTRIENT` (Zinc Sulphate, Boron, Foliar sprays)
  5. `SOIL_AMENDMENT` (Agricultural Dolomitic Lime, Gypsum)
  6. `PESTICIDE` (Broad-spectrum chemical pesticides)
  7. `INSECTICIDE` (Deltamethrin, Malathion, Lambda-cyhalothrin)
  8. `HERBICIDE` (2,4-D Amine, Glyphosate, Pyroxsulam)
  9. `FUNGICIDE` (Mancozeb, Propiconazole)
  10. `SEED_TREATMENT` (Apron Star, Thiram)
  11. `GROWTH_REGULATOR` (Ethephon, Gibberellic acid)
  12. `OTHER`
- **Key Fields**:
  - `uuid` (UUID)
  - `input_code` (VARCHAR, e.g., `FERT-UREA`, `INP-DELTAMETHRIN-01`)
  - `trade_name` (VARCHAR, e.g., "Decis Deltamethrin 2.5% EC")
  - `input_category` (VARCHAR, Enum value above)
  - `nutrient_composition` / Active Ingredients (VARCHAR)
  - `manufacturer` / Supplier (VARCHAR)
  - `application_method` (VARCHAR, e.g., "Foliar spray", "Basal soil application")
  - `recommended_crops` (VARCHAR, e.g., "Wheat, Teff, Barley, Maize")
  - `recommended_dosage` (VARCHAR, e.g., "0.5 L/ha in 200L water")
  - `license_number` (VARCHAR, e.g., "MOA-REG-INS-2023-089")
  - `safety_precautions` (VARCHAR, e.g., "PHI: 14 days; Wear PPE")
  - `is_active` (BOOLEAN)

#### 4. Livestock Breeds (`livestock` / `g2p_register_livestock_catalogs`)
- **Key Fields**:
  - `uuid` (UUID)
  - `breed_code` (VARCHAR, e.g., `1.01.01`)
  - `breed_name` (VARCHAR, e.g., "Abergele", "Borana", "Fogera")
  - `species` (VARCHAR: `CATTLE`, `SHEEP`, `GOAT`, `CAMEL`, `BEEHIVE`)
  - `breed_type` (VARCHAR: `Indigenous`, `Exotic`, `Cross`)
  - `abbreviation` (VARCHAR, e.g., `ABE`, `BOR`)
  - `primary_purpose` (VARCHAR: `DAIRY`, `MEAT`, `DUAL_PURPOSE`, `DRAFT_POWER`, `HONEY`, `WOOL`)
  - `in_national_standard` (BOOLEAN)
  - `in_etlits_registry` (BOOLEAN)
  - `origin_country` (VARCHAR)
  - `average_mature_weight_kg` (NUMERIC)

#### 5. Administrative Geolocation (`locations` / `g2p_register_location_catalogs`)
Standardized 4-level Ethiopian administrative hierarchy (21,053 total administrative units):
- **Levels**:
  - Level 1: **14 Regions** (e.g. `ET01` Tigray, `ET03` Amhara, `ET04` Oromia)
  - Level 2: **125 Zones**
  - Level 3: **1,379 Woredas**
  - Level 4: **19,535 Kebeles**
- **Key Fields**:
  - `uuid` (UUID)
  - `location_code` (VARCHAR, e.g., `ET01`, `ET0301`, `ET030101`, `ET030101001`)
  - `location_name` (VARCHAR)
  - `admin_level` (VARCHAR: `REGION`, `ZONE`, `WOREDA`, `KEBELE`)
  - `parent_location_code` (VARCHAR)
  - `parent_location_name` (VARCHAR)
  - `pcode` (VARCHAR)

## 3. Database UUIDv4 Architecture & Backfill

### 3.1 Extension Requirement
The PostgreSQL extension `"uuid-ossp"` is activated in `catalog_registry_db`:
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

### 3.2 Tables with UUIDv4 Integration
Every catalog table carries a non-null, unique UUID column:
```sql
ALTER TABLE <table> ADD COLUMN IF NOT EXISTS uuid UUID DEFAULT public.uuid_generate_v4() NOT NULL UNIQUE;
CREATE UNIQUE INDEX IF NOT EXISTS idx_<table>_uuid ON <table>(uuid);
```
Covered across **all 22 catalog tables**:
1. **Master Reference Taxonomies**: `crop_catalog`, `crop_categories`, `crop_varieties`, `ecological_zones`, `seed_crops`, `seed_varieties`, `seed_catalog`, `livestock_breeds`, `livestock_types`, `livestock_catalog`, `geo_regions`, `geo_zones`, `geo_woredas`, `geo_kebeles`, `geography_units`.
2. **Live Registry Tables**: `g2p_register_crop_catalogs`, `g2p_register_seed_catalogs`, `g2p_register_input_catalogs`, `g2p_register_fertilizer_catalogs`, `g2p_register_livestock_catalogs`, `g2p_register_location_catalogs`.
3. **Audit History & Intake Forms**: `g2p_register_history_*`, `g2p_intake_form_*`.

## 4. Canonical Read-Only `/v1` API Reference

All `/v1` endpoints are **strictly read-only (`GET` only)**. Any attempt to send `POST`, `PUT`, or `DELETE` requests is blocked at the HTTP routing layer with `HTTP 405 Method Not Allowed`.

Base URL: `http://<host>:8002/v1`

### 4.1 Endpoints Specification

| Endpoint | Method | Filters & Query Parameters | Description |
|:---|:---:|:---|:---|
| `/v1/releases/current` | `GET` | — | Current catalogue release metadata, schema version, and checksum. |
| `/v1/catalogues` | `GET` | — | Summary list and record counts for all 5 master catalogues. |
| `/v1/catalogues/{code}/values` | `GET` | `search`, `category`, `status`, `page`, `page_size` | Unified query router for any catalogue (`crops`, `seeds`, `inputs`, `livestock`, `locations`). |
| `/v1/catalogue-values` | `GET` | `catalogue_code`, `limit` | Compact option tuples (`code`, `display_name`, `uuid`) for UI dropdowns. |
| `/v1/inputs` | `GET` | `category`, `manufacturer`, `crops`, `search`, `page`, `page_size` | List and search agro-inputs and fertilizers. |
| `/v1/inputs/{code_or_uuid}` | `GET` | — | Single agro-input record by either natural code or UUID. |
| `/v1/crops` | `GET` | `category`, `ecological_zone`, `search`, `page`, `page_size` | List and search agricultural crops. |
| `/v1/crops/{code_or_uuid}` | `GET` | — | Single crop record by either `crop_code` or UUID. |
| `/v1/crop-varieties/{code_or_uuid}` | `GET` | — | Single crop/seed variety by code or UUID (alias for seed-varieties). |
| `/v1/seed-varieties` | `GET` | `crop_name`, `is_certified`, `release_year`, `search`, `page`, `page_size` | List and search certified/released seed varieties. |
| `/v1/seed-varieties/{code_or_uuid}` | `GET` | — | Single seed variety record by `seed_code` or UUID. |
| `/v1/livestock/species` | `GET` | — | Distinct species list (`CATTLE`, `SHEEP`, `GOAT`, `CAMEL`, `BEEHIVE`). |
| `/v1/livestock/breeds` | `GET` | `species`, `breed_type`, `primary_purpose`, `search`, `page`, `page_size` | List and search livestock breeds. |
| `/v1/livestock/breeds/{code_or_uuid}` | `GET` | — | Single breed record by `breed_code` or UUID. |
| `/v1/livestock/reference-data` | `GET` | — | Standard reference sets: gender types, production types, and record statuses. |
| `/v1/geography/levels` | `GET` | — | Administrative levels hierarchy definition (Region, Zone, Woreda, Kebele). |
| `/v1/geography/units` | `GET` | `level`, `parent_code`, `search`, `page`, `page_size` | List and search administrative geography units. |
| `/v1/geography/units/{code_or_uuid}` | `GET` | — | Single location record by `location_code`, `pcode`, or UUID. |
| `/v1/snapshots/current` | `GET` | — | Complete registry snapshot summary across all catalogues. |

### 4.2 Caching & ETag Behavior
All successful responses return:
- `ETag: "<sha256-hash>"`
- `Cache-Control: public, max-age=300`
- `X-Catalogue-Release: ETH-master-catalog-v1`

When consumers send the `If-None-Match: "<etag>"` request header, the server validates the hash and returns `HTTP 304 Not Modified` with zero response body, drastically saving network bandwidth.

### 4.3 Example Queries

```bash
# 1. Check current release metadata
curl -s http://localhost:8002/v1/releases/current | jq .

# 2. Get catalogue overview and live counts
curl -s http://localhost:8002/v1/catalogues | jq .

# 3. Compact dropdown options for input categories
curl -s "http://localhost:8002/v1/catalogue-values?catalogue_code=input_categories" | jq .

# 4. Search agro-inputs by category (e.g. INSECTICIDE)
curl -s "http://localhost:8002/v1/inputs?category=INSECTICIDE" | jq .

# 5. Dual lookup by code or UUID
curl -s "http://localhost:8002/v1/inputs/INP-DELTAMETHRIN-01" | jq .
curl -s "http://localhost:8002/v1/inputs/94f46e61-d060-4956-afaa-23dfbe3b4ac8" | jq .

# 6. Search crops by name
curl -s "http://localhost:8002/v1/crops?search=Teff" | jq .

# 7. Seed varieties for a specific crop with pagination
curl -s "http://localhost:8002/v1/seed-varieties?crop_name=Teff&page=1&page_size=10" | jq .

# 8. List administrative regions
curl -s "http://localhost:8002/v1/geography/units?level=Region" | jq .

# 9. Verify ETag caching
curl -i -s -H 'If-None-Match: "032e9a22bb86acf8b694b41866203a27"' http://localhost:8002/v1/releases/current
# Output: HTTP/1.1 304 Not Modified
```

### 5.3 Database Initialization & Migration Sequence

Deploying catalog data to a fresh PostgreSQL database requires the following exact sequence:

#### Step 1: Enable UUID Extension & Create Database
```bash
psql -h $PGHOST -U $PGUSER -p $PGPORT -c "CREATE DATABASE catalog_registry_db;"
psql -h $PGHOST -U $PGUSER -p $PGPORT -d catalog_registry_db -c "CREATE EXTENSION IF NOT EXISTS \"uuid-ossp\";"
```

#### Step 2: Initialize Master & Location Tables
Execute the provided DDL scripts:
```bash
psql -h $PGHOST -U $PGUSER -p $PGPORT -d catalog_registry_db -f scripts/init_catalog_tables.sql
psql -h $PGHOST -U $PGUSER -p $PGPORT -d catalog_registry_db -f scripts/init_location_tables.sql
```

#### Step 3: Register OpenG2P Metadata & Policies
Seed the OpenG2P dynamic UI schema and register definitions:
```bash
psql -h $PGHOST -U $PGUSER -p $PGPORT -d catalog_registry_db -f scripts/init_location_metadata.sql
python3 scripts/seed_catalog_metadata.py
```

#### Step 4: One-Click Automated Master Deployment
Alternatively, use the idempotent deployment script [deploy_catalog_data.sh](file:///home/megha/Videos/gen%202%20last%20aug%2018/catalog-extension/scripts/deploy_catalog_data.sh) which handles steps 1–3 and backfills all 21,053 locations, 1,206 seeds, 156 crops, 94 livestock breeds, and 11 agro-inputs:

```bash
cd catalog-extension
PGHOST=localhost PGPORT=5445 PGDATABASE=catalog_registry_db PGUSER=postgres PGPASSWORD=postgres ./scripts/deploy_catalog_data.sh
```

### 5.6 Troubleshooting & SRE Runbook

#### Issue 1: `function public.uuid_generate_v4() does not exist`
- **Cause**: The PostgreSQL database was initialized without the `uuid-ossp` extension.
- **Remedy**: Connect to `catalog_registry_db` as a superuser and run:
  ```sql
  CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
  ```

#### Issue 2: PostgreSQL Advisory Lock Stuck on Startup (`pg_try_advisory_lock(939392)`)
- **Cause**: A previous worker was killed mid-migration leaving the advisory lock held.
- **Remedy**: Clear the lock in PostgreSQL:
  ```sql
  SELECT pg_advisory_unlock(939392);
  -- If lock persists:
  SELECT pg_advisory_unlock_all();
  ```

#### Issue 3: OpenG2P Staff UI Shows Masked Data (`****`) or Masked Section Headers
- **Cause**: Core OpenG2P `_build_register_policy_condition` evaluates data masking rules. If an unhandled policy condition or async wrapper mismatch occurs, default masking is applied.
- **Remedy**: Ensure the smart-patch in [app.py](file:///home/megha/Videos/gen%202%20last%20aug%2018/catalog-extension/src/openg2p_registry_catalog_extension/app.py) (`_patch_policy_builder`) is active. It intercepts sync vs async calls and allows unmasked read access for authenticated staff.

#### Issue 4: External Consumer Cannot Access `/v1` Endpoints (401 Unauthorized)
- **Cause**: Upstream OpenG2P `BaseController` routes may inherit Keycloak bearer token guards if placed inside `openg2p_registry_core.controllers`.
- **Remedy**: [V1ReadOnlyCatalogController](file:///home/megha/Videos/gen%202%20last%20aug%2018/catalog-extension/src/openg2p_registry_catalog_extension/controllers/v1_readonly_controller.py) mounts public `GET` routes on `self.router` directly without IAM dependency injection, deliberately bypassing Keycloak authentication for read-only consumption.
